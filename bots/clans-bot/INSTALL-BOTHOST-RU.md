# WARDOGS RU Clan Bot — установка на BOTHOST

Инструкция рассчитана на кланового Discord-бота WARDOGS RU и размещение его на `https://bothost.ru`. Бот работает через постоянное Discord Gateway-соединение, поэтому домен, webhook и открытый HTTP-порт ему не нужны.

## 1. Что понадобится

- аккаунт BOTHOST;
- платный тариф с постоянным хранилищем и загрузкой ZIP-архивов;
- приложение Discord с токеном бота;
- права управления сервером WARDOGS RU;
- сайт `wardogs-ru.ru` с файлами `clan-sync.php`, `data/clans.json` и страницей `/clans/`;
- два разных случайных секрета: для сайта и для резервных копий.

Не используйте бесплатный тариф для рабочего запуска. Клановая система хранит `state.json` и локальные копии между перезапусками, поэтому ей необходимо постоянное хранилище `/app/data`.

В документации BOTHOST названия платных тарифов на разных страницах могут отображаться как Basic/Pro или Стандарт/Премиум. Выбирайте не по названию, а по наличию двух функций: **загрузка из архива** и **постоянное хранилище**.

## 2. Создание Discord-приложения

1. Откройте `https://discord.com/developers/applications`.
2. Нажмите **New Application**.
3. Назовите приложение `WARDOGS RU Clans`.
4. Откройте раздел **Bot** и создайте бота.
5. В разделе **Privileged Gateway Intents** включите только **Server Members Intent**.
6. `Message Content Intent` этому боту не требуется.
7. Нажмите **Reset Token**, скопируйте токен и временно сохраните его в менеджере паролей.

Не публикуйте токен, не добавляйте его в архив и не отправляйте в Discord.

### Приглашение бота

1. В Developer Portal откройте **OAuth2 → URL Generator**.
2. Включите scopes:
   - `bot`;
   - `applications.commands`.
3. Выдайте разрешения:
   - View Channels;
   - Manage Channels;
   - Manage Roles;
   - Send Messages;
   - Embed Links;
   - Attach Files;
   - Read Message History;
   - Manage Threads;
   - Connect;
   - Speak;
   - Move Members.
4. Перейдите по созданной ссылке и добавьте бота на сервер WARDOGS RU.
5. В Discord откройте **Настройки сервера → Роли** и переместите роль бота выше всех будущих клановых ролей.

Право `Administrator` выдавать не нужно.

## 3. Подготовка синхронизации с сайтом

Если страница кланов уже установлена и `clan-sync.php` настроен, переходите к следующему разделу.

В публичном каталоге домена должны находиться:

```text
wardogs-ru.ru/
├── clan-sync.php
├── clans/
│   └── index.html
└── data/
    └── clans.json
```

Рядом с публичным каталогом сайта создайте закрытую конфигурацию:

```text
data/www/
├── private-config/
│   └── clans-secret.php
└── wardogs-ru.ru/
    └── clan-sync.php
```

Возьмите файл `site-sync/clans-secret.example.php`, переименуйте его в `clans-secret.php` и поместите вне публичной папки домена.

Создайте секрет длиной 64 шестнадцатеричных символа:

```bash
openssl rand -hex 32
```

Запишите его в конфигурацию:

```php
<?php
return [
    'secret' => 'ВАШ_64_СИМВОЛЬНЫЙ_СЕКРЕТ',
    'allowed_ip' => '',
];
```

Для BOTHOST оставьте `allowed_ip` пустым, пока поддержка хостинга не подтвердит вам постоянный исходящий IP. Доступ всё равно защищён HMAC-подписью и временной меткой.

Откройте в браузере:

```text
https://wardogs-ru.ru/clan-sync.php
```

Правильный результат проверки — HTTP `405 method_not_allowed`: браузер отправляет GET, а запись разрешена только подписанным POST-запросом бота.

## 4. Создание ключа резервных копий

Создайте второй, отдельный ключ:

```bash
openssl rand -hex 32
```

Это значение станет `BACKUP_SECRET`. Оно не должно совпадать с `SITE_SYNC_SECRET`.

Сохраните оба секрета в менеджере паролей. Если `BACKUP_SECRET` будет утерян, зашифрованные файлы `.wdbak` восстановить невозможно.

## 5. Выбор тарифа BOTHOST

Для рабочего бота нужен тариф, который предоставляет:

- постоянную работу контейнера;
- постоянное хранилище `/app/data`;
- загрузку проекта из `.zip`;
- не менее 256 МБ RAM.

Для небольшого сообщества ресурсов начального платного тарифа должно быть достаточно. Музыку и аудиопоток бот не воспроизводит: он только создаёт Discord-каналы и перемещает участников.

## 6. Включение загрузки ZIP

1. Зарегистрируйтесь и войдите на `https://bothost.ru`.
2. Откройте профиль.
3. В блоке **Интерфейс** включите **Загрузка бота из архива**.
4. Сохраните настройки.
5. Перейдите в **Мои боты**.
6. Нажмите **Загрузить из архива**.

Если кнопка ведёт на страницу тарифов, текущий тариф не поддерживает архивный деплой.

## 7. Загрузка клан-бота

Используйте архив `wardogs-clans-bot-bothost-role-icons-2026-09-18.zip`.

В мастере укажите:

| Поле | Значение |
|---|---|
| Название | `WARDOGS RU Clans` |
| Платформа | Discord |
| Токен | токен из Discord Developer Portal |
| Язык/шаблон | Node.js или Discord.js |
| Главный файл | `src/index.js` |
| Домен | не нужен |
| Внутренний порт | не нужен |
| Собственный Dockerfile | выключено |

В архиве уже находится `bothost.json`, а `package.json` содержит правильные `main` и `start`, но путь `src/index.js` лучше всё равно указать явно.

Нажмите **Задеплоить** и дождитесь завершения сборки. Не закрывайте мастер во время загрузки файла.

## 8. Переменные окружения

Откройте карточку созданного бота → **Настройки → Переменные окружения** и добавьте:

| Ключ | Значение |
|---|---|
| `GUILD_ID` | `403186008579112973` |
| `SITE_SYNC_URL` | `https://wardogs-ru.ru/clan-sync.php` |
| `SITE_SYNC_SECRET` | секрет из `clans-secret.php` |
| `SITE_CLANS_URL` | `https://wardogs-ru.ru/clans/` |
| `BACKUP_SECRET` | отдельный ключ резервных копий |
| `BACKUP_INTERVAL_HOURS` | `24` |
| `BACKUP_RETENTION` | `30` |
| `DATA_DIR` | `/app/data` |
| `BACKUP_DIR` | `/app/data/backups` |
| `LOG_LEVEL` | `info` |

Опциональные значения:

| Ключ | Когда нужен |
|---|---|
| `ADMIN_ROLE_ID` | запасной ID роли администрации; после `/clan-setup` выбор хранится в состоянии бота |
| `BACKUP_CHANNEL_ID` | добавляется после создания закрытого канала резервных копий |
| `DISCORD_TOKEN` | только если BOTHOST не создал автоматическую переменную `DISCORD_BOT_TOKEN` из поля «Токен» |

Не создавайте пустые переменные `ADMIN_ROLE_ID` и `BACKUP_CHANNEL_ID`: пока значений нет, просто не добавляйте их.

Сохраните переменные и выполните новый деплой или перезапуск бота. Значения секретов не должны выводиться в логах.

## 9. Проверка первого запуска

Откройте runtime-логи. Успешный запуск содержит строку вида:

```text
INFO Ready as WARDOGS RU Clans#0000; guild commands registered
```

Проверьте:

- контейнер имеет статус `running`;
- бот отображается онлайн в Discord;
- появились команды `/clan-setup`, `/clan`, `/recruitment`, `/voice`, `/clan-backup`;
- в логах нет `Missing ... environment variable`, `Invalid token` и `Missing Access`.

## 10. Первоначальная настройка Discord

1. Выполните `/clan-setup` от учётной записи с правами **Управлять сервером** и **Управлять каналами**.
2. В параметре `admin-role` выберите роль администрации, проверяющей заявки.
3. В параметре `role-anchor` выберите обычную роль, под которой должны располагаться клановые роли. Она должна находиться ниже роли бота. Новые роли каждого клана будут выстроены сразу под ней строго сверху вниз: лидер → заместитель → офицер → боец → рекрут.
4. Бот создаст:
   - регистрацию кланов;
   - список кланов;
   - форум набора;
   - журнал действий;
   - закрытый канал резервных копий;
   - закрытую категорию заявок.
5. Убедитесь, что обычный участник не видит журнал и резервные копии.
6. Убедитесь, что обычный участник не может самостоятельно создать публикацию в форуме набора.

Если бот обновляется поверх прежней версии, обязательно повторите `/clan-setup` с обоими параметрами. Команда переставит существующие клановые роли, добавит отсутствующий общий чат и закроет штаб от бойцов и рекрутов.

## 11. Закрепление канала резервных копий

После `/clan-setup`:

1. В Discord включите **Настройки пользователя → Расширенные → Режим разработчика**.
2. Нажмите правой кнопкой на `🔐・резервные-копии`.
3. Выберите **Копировать ID канала**.
4. Добавьте в BOTHOST переменную:

```text
BACKUP_CHANNEL_ID=СКОПИРОВАННЫЙ_ID
```

5. Перезапустите бота.
6. Выполните `/clan-backup create`.
7. Убедитесь, что в закрытом канале появился файл `.wdbak`.
8. Выполните `/clan-backup status` и проверьте время последней успешной копии.

`BACKUP_CHANNEL_ID` особенно важен после полной потери `state.json`: бот сможет найти внешнюю копию, даже если локальные настройки исчезли.

## 12. Полный приёмочный тест

Проводите его с тестового аккаунта, не имеющего административных прав.

1. Нажмите **Подать заявку**.
2. До заполнения второй части загрузите в любой доступный вам Discord-чат два отдельных файла: логотип клана и квадратную иконку клановых ролей. Для логотипа ограничение 256 КБ не применяется; иконка ролей должна весить не более 256 КБ. Поддерживаются PNG, JPG/JPEG и WebP.
3. Для каждого изображения откройте контекстное меню и выберите **Копировать ссылку**. Нужны две прямые ссылки, начинающиеся с `https://cdn.discordapp.com/attachments/` или `https://media.discordapp.net/attachments/`, а не ссылки на сообщения.
4. Заполните обе части формы: ссылку большого изображения вставьте в поле логотипа, ссылку файла до 256 КБ — в отдельное поле иконки ролей.
5. Проверьте появление закрытого тикета.
6. От администратора нажмите **Одобрить** и подтвердите создание клана.
7. Проверьте пять ролей, одинаковую клановую иконку на каждой роли и их порядок под опорной ролью.
8. Проверьте категорию: `💬・общий-чат` доступен всему клану, а `⚔️・штаб-клана` — только лидеру, заместителю и офицеру.
9. В штабе нажмите **Участники**, выберите тестового пользователя и проверьте принятие, смену роли и исключение.
10. Зайдите участником в `➕・Создать комнату` и проверьте автоматическое создание временного голоса.
11. Создайте карточку набора и проверьте, что в форуме появилась ровно одна публикация с кнопкой **Подать заявку в клан**.
12. От тестового аккаунта отправьте заявку. Закрытый тикет должен появиться внутри категории клана и быть доступен кандидату и руководству, но недоступен бойцам и рекрутам.
13. Примите заявку из тикета и убедитесь, что кандидату выдана роль рекрута.
14. Выполните `/clan sync`.
15. Откройте `https://wardogs-ru.ru/clans/` в приватном окне и проверьте карточку и логотип.
16. Создайте ручной бэкап.

Тестовое восстановление лучше проводить до регистрации реальных кланов.

## 13. Обновление бота

Для бота, созданного из архива:

1. Сначала выполните `/clan-backup create`.
2. В панели BOTHOST откройте карточку бота.
3. Нажмите кнопку загрузки нового архива.
4. Выберите новую версию ZIP.
5. Дождитесь нового деплоя.
6. Проверьте runtime-логи и `/clan-backup status`.

При архивном обновлении BOTHOST сохраняет ID проекта, токен, переменные окружения и данные `/app/data`. Не включайте в ZIP каталоги `data`, `node_modules`, `.git`, а также файл `.env`.

## 14. Восстановление после сбоя

Если код перезапустился, но `/app/data/state.json` сохранился, вмешательство не требуется.

Если `state.json` утрачен:

1. Проверьте, что в переменных BOTHOST сохранены правильные `BACKUP_SECRET`, `GUILD_ID` и `BACKUP_CHANNEL_ID`.
2. Запустите бота.
3. От администратора выполните:

```text
/clan-backup restore-latest confirmation:ВОССТАНОВИТЬ
```

4. Бот загрузит последнюю `.wdbak` из закрытого канала, проверит сервер, шифрование и контрольную сумму.
5. Перед заменой состояния создаст страховочную копию.
6. Восстановит отсутствующие роли, категории, общий чат, штабные и голосовые каналы, роли участников, логотипы и карточки набора.
7. Повторно синхронизирует сайт.

Если были удалены общие каналы регистрации, списка или форума, после восстановления повторите `/clan-setup`. Историю удалённых Discord-каналов восстановить невозможно; будут созданы функциональные замены с новыми ID.

## 15. Диагностика

### `Missing DISCORD_TOKEN or DISCORD_BOT_TOKEN`

BOTHOST не передал токен автоматически. Добавьте вручную переменную `DISCORD_TOKEN` и перезапустите бота.

### `Missing required environment variable: GUILD_ID`

Добавьте `GUILD_ID=403186008579112973` и выполните новый запуск.

### `Cannot find module '/app/index.js'`

В настройках укажите главный файл `src/index.js`, сохраните и выполните именно новый деплой, а не только рестарт.

### `Invalid token`

Сбросьте токен в Discord Developer Portal, обновите поле токена или `DISCORD_TOKEN` в BOTHOST и перезапустите проект. Старый токен после Reset Token больше не работает.

### Команды не появились

Проверьте, что бот приглашён со scope `applications.commands`, `GUILD_ID` правильный, а в логах есть `guild commands registered`.

### Ошибка ролей или `Missing Permissions`

Поднимите роль бота выше опорной и клановых ролей, проверьте `Manage Roles`/`Manage Channels`, затем повторите `/clan-setup` и снова выберите `role-anchor`.

### Логотип не принимается

Проверьте, что вставлена именно прямая ссылка на файл Discord, а не ссылка на сообщение или канал. Логотип должен быть PNG, JPG/JPEG или WebP; ограничение 256 КБ к логотипу не применяется. После загрузки файла в Discord откройте его контекстное меню и нажмите **Копировать ссылку**.

### Иконка ролей не принимается

Иконка ролей должна быть отдельным PNG, JPG/JPEG или WebP-файлом размером не более 256 КБ. Если бот сообщает об отсутствии `ROLE_ICONS`, Discord не разрешает устанавливать изображения ролей на этом сервере. Эта возможность определяется самим Discord и не может быть включена правами бота.

### Состав не пересчитывается

В Developer Portal включите **Server Members Intent** и перезапустите бота.

### Сайт не обновляется

1. Выполните `/clan sync`.
2. Проверьте `SITE_SYNC_URL`.
3. Убедитесь, что `SITE_SYNC_SECRET` в BOTHOST совпадает с секретом на REG.RU.
4. Проверьте права записи для `data/clans.json`.
5. Если PHP отвечает `401 invalid_signature`, проверьте секрет и корректность времени.
6. Если отвечает `403 forbidden`, очистите `allowed_ip` либо укажите подтверждённый исходящий IP BOTHOST.
7. Если отвечает `503 not_configured`, PHP не нашёл `private-config/clans-secret.php`.

### Бэкап не создаётся

Проверьте `BACKUP_SECRET`, `BACKUP_CHANNEL_ID`, права Attach Files и доступ бота к закрытому каналу.

### Данные пропали после обновления

Проверьте, что установлены:

```text
DATA_DIR=/app/data
BACKUP_DIR=/app/data/backups
```

И что тариф предоставляет постоянное хранилище. Не храните рабочие данные в корне `/app`.

### Статус `restarting`

Откройте runtime-логи и найдите первую ошибку. Чаще всего причина — отсутствующая переменная, неверный главный файл или токен.

## 16. Контроль безопасности

- Не выдавайте `Administrator`.
- Не загружайте `.env` и реальные секреты в архив.
- Не публикуйте токен или ключи в тикетах поддержки без защищённого способа передачи.
- Храните `BACKUP_SECRET` вне BOTHOST ещё как минимум в одном защищённом месте.
- Оставляйте канал резервных копий закрытым от `@everyone`.
- Перед каждым обновлением создавайте ручную копию.
- После изменения токена или ключей сразу выполняйте новый тестовый бэкап.
