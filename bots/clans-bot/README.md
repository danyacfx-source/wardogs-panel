# WARDOGS RU — бот клановой системы

Постоянно работающий Discord-бот для одного сервера WARDOGS RU. Он принимает заявки через закрытые тикеты, требует ручного подтверждения администратора, создаёт роли и закрытые каналы клана, считает участников на сервере, управляет временными голосовыми комнатами, синхронизирует публичный реестр с `wardogs-ru.ru/clans/` и автоматически выгружает зашифрованные резервные копии.

## Что создаёт команда настройки

Команда `/clan-setup admin-role:@Администрация role-anchor:@Опорная-роль` создаёт или повторно использует:

- `══ КЛАНОВАЯ СИСТЕМА ══`;
- `🛡️・регистрация-кланов` — панель подачи заявки;
- `📜・список-кланов` — публичные карточки одобренных кланов;
- `📢・агитация-кланов` — один общий Discord Forum;
- `🔒・журнал-кланов` — закрытый аудит действий;
- `🔐・резервные-копии` — закрытые зашифрованные бэкапы для восстановления;
- `══ ЗАЯВКИ КЛАНОВ ══` — закрытые тикеты.

После одобрения создаются пять ролей строго по старшинству — лидер, заместитель, офицер, боец, рекрут — сразу под выбранной опорной ролью. В категории появляются общий текстовый чат для всех участников, закрытый штаб только для руководства, постоянный голосовой канал и канал `➕・Создать комнату`. Заявитель считается лидером и автоматически получает роль `Название Лидер`.

При регистрации требуются два отдельных изображения. Логотип клана используется в Discord-карточках и на сайте и больше не ограничен 256 КБ. Иконка ролей используется для всех пяти клановых ролей и должна весить не более 256 КБ. Для обоих файлов принимаются прямые ссылки на вложения Discord в формате PNG, JPG/JPEG или WebP. Руководство может заменить логотип из панели штаба.

Изображение роли доступно только на серверах, которым Discord предоставляет функцию `ROLE_ICONS`. Бот проверяет её до создания ролей. Если функция недоступна, заявка остаётся необработанной, а администратор получает понятное сообщение; частично созданных ролей не остаётся.

## Команды

- `/clan-setup` — первоначальная идемпотентная настройка, только администрация.
- `/clan invite` — выдать участнику роль рекрута.
- `/clan role` — назначить внутреннюю роль.
- `/clan remove` — убрать все роли этого клана.
- `/clan count` — показать фактический и заявленный состав.
- `/clan dissolve` — распустить клан после ввода его тега; администратор может указать тег нужного клана.
- `/clan sync` — вручную пересчитать все составы и обновить сайт, только администрация.
- `/recruitment create|edit|toggle|delete` — одна форум-публикация набора на клан.
- `/voice name|limit|lock|unlock` — настройка временной комнаты её создателем.
- `/clan-backup status` — состояние автоматического резервирования.
- `/clan-backup create` — немедленно создать и выгрузить зашифрованную копию.
- `/clan-backup restore-latest confirmation:ВОССТАНОВИТЬ` — восстановить последнюю копию; только администрация.

Участникам намеренно запрещено самостоятельно создавать публикации в общем форуме. Публикацию создаёт бот, поэтому ограничение «одна карточка на клан» нельзя обойти обычной кнопкой Discord.

В карточке открытого набора есть кнопка «Подать заявку в клан». Кандидат заполняет форму, после чего внутри категории клана создаётся закрытый тикет, доступный только кандидату, руководству клана и администрации. Лидер, заместитель или офицер принимает кандидата рекрутом либо отклоняет заявку с причиной.

## Переменные окружения

На Bothost добавляйте значения через раздел «Переменные окружения»; для VPS можно скопировать `.env.example` в `.env`. Никогда не отправляйте `.env`, токен или секрет синхронизации в Discord, Git и чат поддержки.

- `DISCORD_TOKEN` — токен приложения из Developer Portal. На Bothost также поддерживается автоматически создаваемая переменная `DISCORD_BOT_TOKEN`.
- `GUILD_ID` — `403186008579112973`.
- `ADMIN_ROLE_ID` — необязательный запасной ID роли; выбранная в `/clan-setup` роль сохраняется ботом.
- `SITE_SYNC_URL` — `https://wardogs-ru.ru/clan-sync.php`.
- `SITE_SYNC_SECRET` — тот же случайный секрет, что хранится вне `public_html` на REG.RU.
- `BACKUP_SECRET` — отдельный ключ шифрования резервных копий, минимум 32 символа. Храните его в менеджере паролей.
- `BACKUP_CHANNEL_ID` — необязательный ID закрытого канала резервных копий; особенно полезен, если локальный `state.json` утрачен.
- `BACKUP_INTERVAL_HOURS` — период автоматической выгрузки, от 1 до 168 часов; по умолчанию 24.
- `BACKUP_RETENTION` — сколько последних копий оставлять локально и в Discord, от 3 до 90; по умолчанию 30.
- `DATA_DIR` — каталог рабочего состояния; на Bothost укажите `/app/data`.
- `BACKUP_DIR` — каталог локальных копий; на Bothost укажите `/app/data/backups`.

Рабочее состояние находится в `DATA_DIR/state.json`, локальные зашифрованные копии — в `BACKUP_DIR`, а внешние копии — в закрытом Discord-канале. На Bothost оба пути должны находиться внутри постоянного хранилища `/app/data`. Бэкап содержит настройки системы, заявки, сведения и наборы кланов, связи ролей/каналов/публикаций и снимок членства по внутренним ролям. Токен Discord, `SITE_SYNC_SECRET`, `BACKUP_SECRET` и содержимое `.env` в него намеренно не включаются.

## Восстановление

Команда восстановления сначала загружает и проверяет последнюю копию из Discord: формат, сервер, AES-GCM-аутентификацию, контрольную сумму и размер. Затем она создаёт страховочную копию текущего состояния, атомарно заменяет `state.json`, возвращает отсутствующие клановые роли, категории, штабные и голосовые каналы, назначает сохранённые роли доступным участникам, восстанавливает публичные карточки и повторно синхронизирует сайт.

Если были удалены общесистемные каналы регистрации, списка или форума, после восстановления повторите `/clan-setup`. Discord не позволяет вернуть удалённым объектам прежние ID и историю сообщений: бот создаст функциональные замены с новыми ID.

## Важные ограничения

- Бот обслуживает только сервер из `GUILD_ID`.
- Подавший заявку аккаунт становится лидером. Поле «Ник лидера» используется для отображения.
- «Общий состав» вводится лидером и включает игроков вне сервера; бот не может проверить чужой Discord-сервер.
- «На сервере» вычисляется автоматически как число уникальных пользователей с любой ролью конкретного клана.
- Логотип клана обязателен и принимается только по прямой ссылке на вложение Discord CDN; ограничение 256 КБ к нему не применяется.
- Отдельная иконка ролей обязательна, принимается в PNG, JPG/JPEG или WebP и ограничена 256 КБ. Она назначается всем пяти клановым ролям.
- Изображение карточки набора необязательно и также принимается только по ссылке на вложение Discord CDN.
- Удаление клана затрагивает только ID ролей и каналов, записанные при его создании ботом.
- Без сохранённого `BACKUP_SECRET` зашифрованные архивы расшифровать невозможно. Этот ключ должен храниться отдельно от хостинга.

## Безопасность

Боту не требуется право `Administrator`. Дайте только перечисленные в инструкции разрешения. Роль бота должна находиться выше всех создаваемых клановых ролей. Бэкапы сжимаются и шифруются AES-256-GCM с ключом, полученным через `scrypt`; подменённый, повреждённый, слишком большой архив или архив другого Discord-сервера отклоняется. Запись локальных файлов выполняется атомарно с правами `600`. PHP-мост принимает только подписанный POST, ограничивает размер и схему JSON, проверяет время запроса и атомарно заменяет публичный файл. На сайт не передаются токены, служебные ID каналов и ролей или закрытые сообщения.
