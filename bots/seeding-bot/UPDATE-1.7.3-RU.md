# WARDOGS Seeding Bot 1.7.3: массовое начисление сидерам

Версия 1.7.3 добавляет две административные команды. Все функции версии 1.7.2, включая два сервера и проверку живого статуса Reserved slot, сохранены. Новых переменных окружения нет.

## Обновление на BotHost

1. Сделайте `/seed-admin backup`, сохраните каталог `/app/data` вместе с `seeding.sqlite`.
2. Остановите старый бот и загрузите `WARDOGS-Seeding-Bot-BotHost-v1.7.3-Node20.zip` в тот же проект. Главный файл — `index.js`, Node.js — 20. Выполните полный деплой.
3. Оставьте прежние токен Discord, оба пароля WDRCON, ключи шифрования, адреса серверов и переменные донатной интеграции. База и история баллов сохраняются. После запуска бот зарегистрирует новые команды `/seed-admin` в Discord.
4. Убедитесь, что `/seed-admin health` работает и `/seed-admin seeders` показывает нужное число действующих привязок.

## Баллы всем сидерам

Для объявленной компенсации за второй сервер сначала посмотрите число получателей:

```text
/seed-admin points-all amount:20 reason:компенсация_за_второй_сервер operation_id:server2-comp-2026-09 confirm:false
```

Затем выполните **ту же команду** с `confirm:true`. Каждому действующему подтверждённому сидеру будет добавлено 20 баллов. Баланс изменится, время и недельный рейтинг — нет.

## Время всем сидерам

```text
/seed-admin time-add-all minutes:30 reason:сбой_учёта_29_09 operation_id:outage-2026-09-29 confirm:false
```

После просмотра числа получателей повторите её с `confirm:true`. Бот прибавит каждому 30 минут к текущей неделе по Москве и общему времени. Баллы за эти минуты рассчитываются отдельно для каждого по тем же правилам, что и `/seed-admin time-add`: первые 60 минут ручных корректировок — 1 балл за 6 минут, затем 1 балл за 3 минуты. Карточка текущего рейтинга обновляется сразу, если Discord доступен, иначе при очередном автоматическом обновлении.

## Кого затрагивают команды

- Все сидеры с действующей подтверждённой привязкой через `/seed link` на момент начисления. Наличие сидинга в текущей неделе для получения баллов не требуется.
- Отдельные привязки `/vip-link` без роли сидера, а также отвязанные архивные аккаунты исключены.
- Обе команды доступны только администратору с правом **Manage Server** и одной из настроенных ролей `DISCORD_ADMIN_ROLE_IDS`. Ответ виден только вызвавшему команду.
- `operation_id` — уникальное имя **одного** начисления: 3–64 символа, латинские буквы, цифры, `_` и `-`. Повтор команды с тем же ID не начисляет повторно, включая повтор после перезапуска бота. Для другого начисления придумайте новый ID.
- Список получателей определяется по базе в момент выполнения. Изменения балансов, времени, индивидуальных записей журнала баллов и общего аудита выполняются одной транзакцией. Если она не завершится, изменения откатятся для всех участников.
