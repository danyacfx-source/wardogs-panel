# WARDOGS | RU · сбор игроков · версия 1.8.0

В версии 1.8.1 для роли сбора `859738052666327040` добавлены `/seed-gather start/status/stop`. Описанные ниже команды `/seed-admin` сохранены для основных администраторов. Обновление прав — [UPDATE-1.8.1-RU.md](UPDATE-1.8.1-RU.md).

## Запуск сбора

В обычном текстовом канале выполните **`/seed-admin gather`** и выберите в параметре **`server`** нужный сервер:

- **Сервер 1** — первый сервер из действующей настройки `WARDOGS_RCON_URL`.
- **Сервер 2** — второй сервер из `WARDOGS_RCON_2_URL`, по умолчанию `http://216.144.249.92:7789`.

Адреса выше — адреса API WDRCON. Игрокам не нужно подключаться к этому порту. Кнопка в карточке показывает игровое название сервера и инструкцию для игры.

В примерах ниже `main` и `second` — значения вариантов «Сервер 1» и «Сервер 2». В интерфейсе Discord выбирайте вариант из выпадающего списка.

```text
/seed-admin gather server:second
```

По умолчанию бот:

1. Уведомляет роль **«Сидер»** (`1552728825568174090`, либо вашу текущую настройку `SEEDER_ROLE_ID`).
2. Публикует в канале запуска оформленную карточку выбранного сервера.
3. Ставит цель **20 игроков** и срок сбора **120 минут**.
4. Обновляет карточку с интервалом `SEED_TICK_SECONDS`: по умолчанию раз в **30 секунд**.
5. Показывает реальное количество игроков, например **«Сейчас 12/20 — нужно ещё 8»**, и полосу прогресса.
6. Даёт всем участникам кнопку **«Как подключиться»**. Ответ на кнопку виден только нажавшему её участнику.
7. При достижении или превышении цели меняет карточку на итоговую и публикует отдельное сообщение об успехе. Уведомление о достижении цели создаётся один раз для этого сбора.

## Дополнительные параметры

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `server` | Сервер 1 или сервер 2. Обязателен. | — |
| `target` | Цель от 2 до 100 игроков. | 20 |
| `role` | Роль, которую бот уведомит. | «Сидер» |
| `channel` | Текстовый канал для карточки. | Канал запуска команды |
| `minutes` | Срок сбора от 15 до 360 минут. | 120 |
| `instructions` | Ваша инструкция подключения: от 3 до 1000 символов. | По игровому названию из RCON |

Пример со своими настройками:

```text
/seed-admin gather server:second target:20 role:@Сидер channel:#сбор minutes:60
```

Если для подключения нужна точная последовательность действий, игровой ID или ссылка, передайте их в `instructions`. Этот текст появится по кнопке вместо стандартной инструкции поиска сервера по названию. Если RCON временно не сообщает название и своей инструкции нет, кнопка честно сообщает, что название ещё не получено.

Выбирайте канал, доступный участникам уведомляемой роли.

## Проверка и остановка

```text
/seed-admin gather-status server:second
/seed-admin gather-stop server:second
```

`gather-status` проверяет текущий сбор, обновляет его карточку и показывает состояние администратору. `gather-stop` отменяет активный сбор и меняет публичную карточку на завершённую. Новое сообщение с упоминанием роли при отмене не отправляется.

Для каждого сервера может идти **один активный сбор**. Оба сервера можно собирать одновременно: численность в карточках учитывается отдельно, игроки двух серверов не складываются для достижения цели одного сервера. После достижения цели сбор завершается; последующее уменьшение онлайна не запускает его повторно. Для нового сбора снова используйте команду.

Новый сбор на одном сервере можно объявлять не чаще раза в **10 минут**. Повторный запуск при уже активном сборе возвращает текущую карточку и не уведомляет роль повторно. Если на сервере уже достаточно игроков, новая рассылка не создаётся.

## Сбои и перезапуск

- При потере связи с игровым сервером карточка показывает, что численность уточняется. Последние данные помечаются как последние известные; сбой не считается нулевым онлайном и не вызывает ложного сообщения об успехе.
- Данные сбора сохраняются в действующей зашифрованной базе `seeding.sqlite`. После перезапуска активный сбор продолжает обновляться; истёкший закрывается по своему сроку.
- Неотправленные карточки и сообщения об успехе остаются в очереди повторной обработки. При временном сбое Discord исправьте доступ бота и дождитесь следующей проверки либо вызовите `gather-status`.
- При восстановлении удалённой карточки роль повторно не уведомляется. При восстановлении после потерянного ответа Discord бот ищет своё сообщение в недавней истории и использует идентификатор отправки для защиты от повторов.
- Запуск, остановка, истечение срока и достижение цели сохраняются в защищённом журнале аудита.

Сбор может координировать подключение и вне часов начисления сидинга. Время, баллы, роли, VIP и Reserved slot продолжают работать по действующим правилам. Команда не засчитывает время по нажатию кнопки: учитывается реальное присутствие на сервере и выполнение условий сидинга. Сам Discord-бот игровых мест не занимает.

## Права

Команды доступны тем же администраторам, что и остальные `/seed-admin`: право **«Управление сервером»** и одна из ролей, заданных в `DISCORD_ADMIN_ROLE_IDS`.

В канале сбора боту нужны:

- просмотр канала;
- отправка сообщений;
- встраивание ссылок;
- чтение истории сообщений.

Чтобы роль действительно получила уведомление, включите у неё **«Разрешить всем упоминать эту роль»** либо дайте боту в канале право **«Упоминание @everyone, @here и всех ролей»**. Сам бот уведомляет только выбранную роль. Выбор `@everyone` для сбора запрещён.

Карточка сбора не публикуется в защищённых каналах правил, аудита и резервных копий. Кнопка инструкции доступна обычным участникам; административные права и Steam-привязка для её использования не нужны.

## Обновление на BotHost

1. Остановите бот сидинга и сохраните резервную копию его постоянного `DATA_DIR`, включая `seeding.sqlite`, а также прежние переменные и ключи шифрования.
2. Замените файлы программы содержимым архива. Постоянный каталог данных и секреты сохраните.
3. Запустите бота. Команды регистрируются автоматически; в журнале появится `discord_commands_registered`.
4. Проверьте право упоминания роли в выбранном канале. Запустите `/seed-admin gather` для нужного сервера.

**Новые переменные не нужны.** Используются уже настроенные API обоих серверов и действующая роль сидеров. В архиве сохранены команды ручного и массового начисления времени и баллов, интеграция донатного VIP и управление слотами двух серверов.

Проверка версии: `npm run check` и `npm test`. Версия проверена локально: **97 тестов прошли**. На вашем Discord и игровых серверах проверку нужно выполнить после установки с действующими настройками.
