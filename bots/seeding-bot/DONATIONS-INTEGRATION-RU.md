# Бот сидеров WARDOGS 1.6.1 · оплаченный VIP ЮMoney

В сборке **1.7.4** бот сидеров также единолично управляет общей Discord VIP ролью `1552725871830503484`. Она действует, пока активен хотя бы один из двух VIP: оплаченный или за баллы. Донатный бот 1.2.3 проверяет роль при `/donation-admin setup`, но не создаёт и не снимает её. Порядок обновления — в `UPDATE-1.7.4-RU.md`.

Эта версия основана на присланном архиве 1.5.1: сохраняет роли «Сидер» и «Супер сидер», недельный топ-3, защиту постоянного слота, сидинг, баллы, существующую привязку Discord↔SteamID и магазин VIP за баллы. Дополнительно она читает подтверждённые покупки VIP из защищённого журнала сайта донатов и единолично управляет общим reserved slot. Для оплаченного VIP добавлена отдельная привязка `/vip-link`: она не включает участника в сидинг, не выдаёт роль «Сидер» и не начисляет баллы. Спонсорские роли и обычные пожертвования сами по себе игровой слот не создают.

## Обновление BotHost

1. Выполните `/seed-admin backup`, скачайте резервную копию из закрытого канала и дополнительно сохраните постоянный каталог `/app/data`, особенно `seeding.sqlite`. Сохраните прежние значения `DATA_ENCRYPTION_KEY` и `BACKUP_ENCRYPTION_KEY`. Не меняйте ключи при обновлении и не заменяйте базу пустой.
2. Остановите прежний экземпляр сидера и загрузите файлы этой версии в его проект BotHost. Сохраните прежние значения RCON, Discord, каналов и расписания. Для работы нужен Node.js 20.18+; `npm ci` устанавливает зависимости.
3. Добавьте три переменные из `.env.bothost.example`:

   - `DONATION_SITE_BASE_URL=https://wardogs-ru.ru`
   - `DONATION_FEED_TOKEN` — то же значение, что `feed_token` в закрытом конфиге сайта и `FEED_TOKEN` донатного бота.
   - `DONATION_CHECKOUT_SECRET` — то же значение, что `checkout_secret` на сайте и `CHECKOUT_SECRET` донатного бота.

   `DONATION_POLL_SECONDS=45` можно оставить по умолчанию. Секреты не копируйте в исходники или чат.
4. Обновите PHP-файлы сайта до версии, которая записывает подписанный заказ при посещении страницы оплаты. Старые ссылки оплаты обновите: VIP по старой ссылке не содержит подписанный список получателей для игрового доступа.
5. Запустите сидера. `/seed-admin health` должен показать «Оплаченный VIP: журнал платежей доступен». Если журнал недоступен, проверьте HTTPS сайта, три переменные выше и права на `/donate/feed.php`. Сидинг продолжает работать; автоматическое снятие слотов временно откладывается.
6. После обновления донатного бота выполните `/donation-admin setup` в Discord. Проверьте оплаченный VIP: `/donate status` показывает покупку, `/vip-link status` — VIP-привязку и срок. Новый получатель, который не занимается сидингом, заходит на WARDOGS и выполняет `/vip-link link steam_id`, затем `/vip-link verify code`. У уже привязанного сидера SteamID подходит для VIP без повторной привязки.

## Два назначения привязки

- `/vip-link link` и `/vip-link verify` создают **только VIP-привязку**. Пользователь не попадает в список сидеров, не участвует в подсчёте времени и не получает баллы за сидинг.
- `/seed link` и `/seed verify` создают привязку сидера. Такая привязка также подходит для оплаченного VIP.
- Если владелец VIP-привязки захочет стать сидером, он ещё раз подтверждает **тот же SteamID** через `/seed link` и `/seed verify`. После этого его привязка переносится в учёт сидеров, а оплаченный VIP сохраняется. Автоматического перехода нет.
- Отменить отдельную привязку можно через `/vip-link unlink confirm:true` после окончания оплаченного VIP. Для привязки сидера остаётся `/seed unlink confirm:true`.

Новый архив автоматически выдаёт роль «Сидер» после `/seed verify` и снимает её после `/seed unlink`. Привязка `/vip-link` не выдаёт эту роль и не создаёт запись сидера. Недельная награда и защищённые постоянные слоты из версии 1.5.1 сохранены.

## Источники одного слота

| Основание | Время действия | Слот |
| --- | --- | --- |
| Спонсорская роль без VIP | Накопительный порог | Нет |
| Личный или клановый оплаченный VIP | С подтверждённого платежа, календарными месяцами | Получателю с привязанным SteamID |
| VIP за баллы сидера | После появления SteamID в live reserved slots | Да |
| Недельный топ-3 сидеров | До следующего обновления рейтинга | Да |
| Ручное назначение администратора | По решению администратора | Сохраняется |

Если оплаченный VIP пересекается с VIP за баллы или недельной наградой, слот остаётся до окончания последнего действующего права. Защищённый постоянный слот никогда не удаляется автоматической очисткой. Сидер помечает прежний ручной слот как внешний и не снимает его. При недоступности журнала платежей сидер откладывает снятие слота до проверки возможного продления. С версии 1.7.2 бот требует живые команды WDRCON на обоих серверах; если их нет, оплаченный VIP остаётся учтённым, но игровой слот нельзя выдать мгновенно. До появления живого API следует приостановить продажу оплаченного VIP на сайте.

Бот донатов не должен иметь RCON-пароль и не должен запускать свой старый RCON-адаптер. Единственный процесс, который пишет в игровые reserved slots, — этот бот сидеров. Данные `seeding.sqlite` и его зашифрованные резервные копии теперь также включают состояние оплаченных VIP и право владения слотами. Сохраняйте вместе с ними журнал сайта `events.jsonl`, приватные файлы `orders/` и состояние донатного бота `donations.json`.

Если ранее уже были реальные оплаченные VIP на старой версии донатного бота, их сроки требуют отдельной сверки перед переходом: в старом журнале нет подписанного списка получателей для автоматического импорта. Для нового платежа используйте новую ссылку после установки сайта и обоих ботов.
