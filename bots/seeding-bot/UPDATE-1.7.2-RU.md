# Обновление 1.7.2: фактический статус Reserved slot без ожидания рестарта

## Что изменилось

- Бот добавляет и удаляет слот только через живые маршруты WDRCON на **обоих** серверах. После ответа перечитывает `GET /v1/reserved-slots`; ответ API без изменения активного списка не считается успешной выдачей.
- `/seed status` и `/vip-link status` при каждом вызове запрашивают фактический список активных слотов каждого сервера. «Ожидает проверки» не отображается как «активен».
- Магазин VIP за баллы перед списанием проверяет, есть ли на обоих серверах `GET /v1/reserved-slots`, `POST /v1/reserved-slots` и `DELETE /v1/reserved-slots/{id}`. Если нет, покупка отменяется без списания.
- Бот больше не добавляет и не удаляет `DefaultReservedPlayerIds` через `PUT /v1/config`. Привязки, баланс, оплаченные права, постоянная защита и ожидающие заявки в прежней базе сохраняются. Когда игровой сервер получит нужные маршруты, бот повторит синхронизацию.

## Ограничение WARDOGS

Изменение `DefaultReservedPlayerIds` в конфигурации **не меняет активный список игрового процесса**. В наблюдавшихся сборках WDRCON CL-499480/CL-501228 маршруты мгновенной записи слотов отсутствуют. Даже `POST /v1/match/restart` перезагружает матч, но не конфигурацию процесса. Описание измерений и списка маршрутов: <https://github.com/warcon-app/warcon/blob/main/docs/wardogs-api.md>.

Поэтому бот не может включить реальный Reserved slot без рестарта на такой сборке. Для мгновенной работы нужны поддержка живой выдачи и снятия в сборке **каждого** игрового сервера либо предусмотренный разработчиком серверный механизм горячего применения. Изменение одного только бота не добавляет этих команд в WDRCON.

## Перед обновлением

1. На работающей версии 1.7.1 выполните `/seed-admin health`. Если для одного из серверов указан режим «конфигурация + проверка после рестарта», на нём мгновенное управление пока отсутствует. Спросите Qonzer, доступна ли сборка WARDOGS с живыми `POST` и `DELETE /v1/reserved-slots`, и проверьте список `routes` в `GET /v1/capabilities` каждого сервера.
2. Пока живых команд нет на обоих серверах, приостановите продажу **оплаченного VIP** в донатном боте/на сайте: срок оплаченного VIP отсчитывается от платежа и не продлевается из-за отсутствия RCON. Обычные донаты без VIP продолжают работать.
3. Сохраните `/app/data`, сделайте `/seed-admin backup`. При обновлении оставьте прежние токен, пароли WDRCON, `DATA_ENCRYPTION_KEY`, `BACKUP_ENCRYPTION_KEY` и параметры интеграции платежей.

## Установка и проверка

1. Остановите старый экземпляр. Загрузите `WARDOGS-Seeding-Bot-BotHost-v1.7.2-Node20.zip` в тот же проект BotHost; главный файл `index.js`. Сделайте полный деплой. Структура SQLite и остальные переменные не меняются.
2. Выполните `/seed-admin health`. На **каждом** сервере должна появиться строка «мгновенная выдача и снятие доступны». Если показано «мгновенные команды отсутствуют», бот продолжит считать сидинг, но не сможет выдавать и снимать игровые слоты немедленно; покупка VIP за баллы будет отклоняться до списания.
3. На тестовом привязанном аккаунте выполните `/seed-admin reserved-protect`, затем `/seed status` или `/vip-link status`. Оба ответа должны показывать «активен сейчас» только при наличии SteamID в текущем `GET /v1/reserved-slots` соответствующего сервера. Для снятия защиты используется `/seed-admin reserved-unprotect`; сама эта команда по прежнему не удаляет постоянный слот.
4. После подтверждения живых маршрутов на двух серверах выполните `/seed-admin vip-sync`, проверьте ранее ожидавших пользователей и только потом возобновите продажу оплаченного VIP. Перезапуск игровых серверов для последующих операций со слотами в этой схеме не требуется.

### Ранее записанные конфигурационные слоты

Версия 1.7.1 могла оставить SteamID в `DefaultReservedPlayerIds` при отсутствии записи в активном списке. При миграции проверьте такие записи в консоли обоих серверов. Сами по себе они не дают доступ до рестарта; бот 1.7.2 не удаляет их из конфигурации и показывает только фактическое состояние. Если заявка уже истекла, удалите старую отложенную запись средствами панели и убедитесь, что она не появится после следующего запуска игрового процесса. Существующие вручную выданные и защищённые слоты не удаляйте.

Если оба сервера уже предлагают живые команды, но слот всё равно не появляется после ответа `POST`, бот сообщит ошибку `reserved_not_applied` и не назовёт его активным. Передайте Qonzer результат `/seed-admin health`, ответ сервера и версию сборки WARDOGS без RCON-пароля.
