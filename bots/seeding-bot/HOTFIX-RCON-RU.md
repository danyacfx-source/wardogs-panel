# Срочное обновление RCON — версия 1.5.1

## Что означают текущие логи

Строка `bot_ready` подтверждает, что Discord, база и WDRCON успешно прошли проверку при запуске. `backup_created` подтверждает исправную базу и создание резервной копии. Серия `RCON is unreachable`, начавшаяся позже, означает потерю сетевого соединения с WDRCON игрового сервера, а не повреждение базы.

Во время обрыва бот не может подтвердить присутствие игроков на игровом сервере, поэтому начисление безопасно приостанавливается. Уже накопленные баллы, статистика, привязки, резервные копии и очередь VIP сохраняются.

## Что исправлено в 1.5.1

- безопасные GET-запросы автоматически повторяются через новое соединение;
- бот остаётся запущенным при временной недоступности RCON на старте;
- `/seed-admin health` проверяет Discord и базу даже при отключённом RCON и показывает понятную сетевую причину;
- обычные команды, не требующие игрового сервера, продолжают работать;
- пользовательские ошибки больше не записываются как аварии приложения;
- одинаковое предупреждение об обрыве не засоряет лог каждые несколько минут;
- после восстановления появляется событие `rcon_connection_restored`;
- HTML-сайт `rcon.wardogs.com` распознаётся как веб-панель, а не WDRCON endpoint;
- покупка не списывает баллы, если обязательная предварительная проверка RCON не состоялась;
- ожидающие VIP остаются в безопасной очереди и не теряют оплаченный срок.

## Срочные действия в Qonzer

1. Убедитесь, что игровой сервер имеет состояние **Running**. Если нет — запустите его.
2. Откройте конфигурацию WDRCON и проверьте:

```ini
[/Script/WDRCON.WDRCONSettings]
bEnabled=true
Password=ВАШ_ТЕКУЩИЙ_RCON_ПАРОЛЬ
Port=7799
```

3. Не публикуйте пароль и не меняйте его без необходимости. Значение должно посимвольно совпадать с `WARDOGS_RCON_PASSWORD` в BotHost.
4. Проверьте в Qonzer удалённый доступ или port mapping: внешний TCP-порт должен вести на WDRCON `7799`.
5. Разрешите этот порт только для постоянного исходящего IP ноды BotHost. Не открывайте административный HTTP RCON всему интернету.
6. Выполните полный рестарт игрового сервера и дождитесь статуса **Running**.

## Правильный адрес

`WARDOGS_RCON_URL` должен указывать прямо на игровой сервер и WDRCON-порт. Для текущих известных параметров ожидается:

```dotenv
WARDOGS_RCON_URL=http://51.83.166.12:7799
RCON_ALLOW_INSECURE_HTTP=true
```

Используйте этот порт только после подтверждения внешнего сопоставления в Qonzer. Если панель показывает другой публичный порт, укажите его.

Не используйте:

```dotenv
WARDOGS_RCON_URL=http://rcon.wardogs.com
```

Этот адрес открывает статическую браузерную консоль. Она просит пользователя отдельно ввести IP, порт и пароль и не является WDRCON API игрового сервера.

## Обновление BotHost без потери данных

1. В работающей версии выполните `/seed-admin backup` и убедитесь, что файл появился в закрытом канале бэкапов.
2. Остановите бота.
3. Сохраните текущие значения `DATA_ENCRYPTION_KEY`, `BACKUP_ENCRYPTION_KEY`, `WARDOGS_RCON_PASSWORD` и Discord-токена без изменений.
4. Загрузите `WARDOGS-Seeding-Bot-BotHost-v1.5.1-Node20.zip` как полное обновление.
5. Не удаляйте постоянный каталог `/app/data` и не создавайте новую базу.
6. Отключите использование собственного Dockerfile и выполните полный деплой в штатном Node.js 20.20.2.
7. Добавьте или проверьте переменные:

```dotenv
RCON_TIMEOUT_MS=6000
RCON_RETRY_ATTEMPTS=1
RCON_RETRY_BASE_MS=300
RCON_OUTAGE_LOG_INTERVAL_SECONDS=900
```

8. Запустите сначала игровой сервер, затем бота.
9. В логах дождитесь `bot_ready`. Поле `rconState` должно быть `connected`. Значение `degraded` означает, что бот работает, но RCON пока недоступен.
10. Выполните `/seed-admin health`.

## Новые диагностические события

| Событие | Значение |
|---|---|
| `rcon_connection_lost` | связь потеряна; пишется один раз в начале обрыва |
| `rcon_still_unreachable` | RCON всё ещё недоступен; не чаще одного раза в 15 минут |
| `rcon_connection_restored` | связь восстановлена автоматически |
| `startup_rcon_unavailable` | RCON был недоступен при старте, бот запущен в защищённом режиме |
| `interaction_rcon_failed` | команда требовала RCON, но сервер не ответил |
| `wrong_endpoint` | вместо API указан HTML-сайт или панель |

Если после полного рестарта игрового сервера `/seed-admin health` показывает `порт отклонил соединение`, проблема в WDRCON listener или port mapping Qonzer. Если показывает `истёк тайм-аут соединения`, проверяйте firewall и маршрут от BotHost. Если показывает HTTP `401` или `403`, не совпадает пароль или правило доступа.
